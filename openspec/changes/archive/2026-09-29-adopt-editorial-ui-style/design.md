## Context

参见 [proposal.md](proposal.md)。现有前端为 React 18、TypeScript 与单份全局 CSS；登录与材料页由 `App.tsx` 根据服务端 Session 切换。`web-experience` 已规定登录、角色权限、上传和材料纯文本展示行为。当前工作树已有 B 方案实现，本设计用于补齐决策记录并供核验。

## Goals / Non-Goals

**Goals:** 让两页使用同一套可复用的视觉变量和基础样式；在窄屏下保持可用；让后续前端开发能找到并遵循明确的视觉规范。

**Non-Goals:** 不改变 API、身份或上传逻辑；不引入新的 UI 框架、远程字体或北京大学官方标识。

## Decisions

1. **用 CSS 自定义属性管理基础设计值。** 品牌色、纸张色、文字、状态色、常用间距及圆角集中在 `frontend/src/styles.css`。相比在每个页面写独立颜色，这能减少风格漂移；相比引入组件库，保留现有前端的小体量和无新增运行时依赖。
2. **共享品牌组件与基础样式。** 登录页和材料页共用自有 `CC` 字标，表单、按钮、卡片和状态提示共用样式。材料页的列表与教师上传区使用响应式网格；学生单列表占满内容宽度。
3. **保留现有行为入口。** 修改页面层级和类名时保留 `form.login`、`header.bar`、`form.upload`、`.materials` 等浏览器验收选择器。错误状态仍使用 `role="alert"`，成功提示使用 `role="status"`；材料正文继续作为纯文本渲染。
4. **把后续约束放在代码邻近的位置。** `frontend/STYLE_GUIDE.md` 说明设计规则，`frontend/AGENTS.md` 指导后续前端工作，`openspec/config.yaml` 让后续变更规划知道该规范。当前是开发约束，没有新增自动样式 lint 门禁。

## Risks / Trade-offs

- **全局 CSS 可能影响后续页面** → 后续 UI 先复用现有类和变量，并在桌面及窄屏检查；新增特殊样式时明确作用范围。
- **系统衬线字体在不同平台外观不同** → 使用本机字体回退，不依赖网络字体，验收以层级和可读性为准。
- **仅靠文档不能阻止所有风格偏离** → 设计值集中管理并在前端指引、OpenSpec 背景和评审中重复引用；若偏离频繁再引入自动检查。
- **工作树代码早于 OpenSpec 变更** → 按本变更的任务逐项核对现有实现和验证证据，不将补录视为事前审查。

## Migration Plan

该变更只涉及前端静态资源和开发文档，无数据迁移。发布前构建前端并核对现有浏览器验收选择器及关键登录、材料场景；如需回退，回退本变更涉及的前端样式与页面文件即可。
