## Context

参见 [proposal.md](proposal.md)。目前 `MaterialsPage` 在材料列表前渲染整个 `RetrievalPanel`，而 `RetrievalPanel` 同时渲染检索和问答；两组命中/出处默认展示完整摘录。材料详情另接在页面末尾，教师索引表单嵌在列表行内。现有检索 API 与 `IndexPanel` 已具备所需数据和操作，改动集中在前端呈现与状态管理。

视觉继续使用 `frontend/STYLE_GUIDE.md` 与 `styles.css` 中的令牌。设计重点是阅读路径：先选任务，再查看内容，相关操作贴近材料。

## Goals / Non-Goals

**Goals:**

- 让材料列表成为登录后的首屏，问答、检索各有独立且易返回的工作区。
- 长摘录采用渐进展示，完整文本与出处信息始终可获取。
- 阅读材料时保留原任务状态，并提供清楚的关闭与焦点返回路径。

**Non-Goals:**

- 改动检索排序、回答生成、切分策略、API 或服务端授权。
- 替换既定「书卷文雅」配色与字体方向，或引入新 UI 框架。

## Decisions

### 1. 使用同页任务标签组织主要内容

页面头部下方设置「材料」「问答」「检索」标签；默认「材料」。每次只显示当前面板，非当前面板保持挂载但从布局和辅助技术阅读流中隐藏，以保留输入及结果。采用语义化 tablist、选中状态和键盘方向键切换；切换时焦点保持在当前标签，返回后恢复工作区的阅读位置。

```text
+------------------------------------------------------+
| Header: class and account                            |
| [Materials] [Ask] [Search]                            |
+------------------------------------------------------+
| Materials: list + teacher actions                     |
| Ask: question -> answer -> source summaries           |
| Search: query -> ordered compact hits                 |
+------------------------------------------------------+
| Contextual reader opens beside content on desktop     |
| and fills the screen on narrow devices                |
+------------------------------------------------------+
```

相比继续把所有区域垂直排列，标签直接消除长结果对材料位置的影响；相比新建路由，它保持现有单页应用与本次会话状态管理的范围。

### 2. 将检索与问答的交互状态分开维护

从现有 `RetrievalPanel` 提取问答和检索面板，或将两组状态提升到稳定挂载的工作区容器。保留现有请求、401 处理、空结果与故障文案。新提交时只清理对应工作区的旧错误与展开状态，避免一次检索清空问答内容。

教师材料区将上传置于工具栏入口，表单按需展开；材料行保留查看、下载和教师索引入口。索引详情在与当前材料关联的上下文区域打开，避免在每行展开长表单。

### 3. 摘录预览由显式状态控制

命中和出处默认展示有限长度的纯文本预览，保留完整标题、编号和位置。每条有「展开摘录/收起摘录」控件，完整文本仍以 React 文本节点呈现。点击回答中的有效 `[n]` 时，激活第 n 条出处、展开其摘录并滚动到可见位置；无效标记保持普通文本。每次新的结果重置该结果列表的展开状态。

相比只给结果容器设置固定高度和内部滚动，这能让用户先扫描来源，再选择要细读的证据；窄屏也不会出现难以操作的嵌套滚动区域。

### 4. 统一材料阅读的上下文面板

材料列表、命中和出处共用 `openMaterial`，由 `MaterialsPage` 管理详情请求与阅读面板。桌面在当前工作区旁显示阅读面板；窄屏使用占满可用视口的阅读层。打开时记录触发控件和工作区阅读位置，关闭时恢复焦点与阅读位置；Escape 与可见关闭按钮均可关闭。加载、错误和 401 沿用现有处理，正文继续在 `<pre>` 中安全显示。

阅读面板和教师索引面板使用相同的上下文位置，但状态互斥。这样列表与查找结果保持原位，长内容在自己的阅读区域滚动。

### 5. 沿用现有视觉令牌并收紧信息层级

保留米白页面、纸张色内容面、北大红主要操作与既有字体。工作区标签使用清晰选中态，答案优先于出处，材料标题优先于技术元数据；每个区域只突出一个主要动作。新增样式复用 `--brand`、`--paper`、`--canvas`、间距与边框令牌。桌面和约 390px 宽度分别检查信息顺序、触控尺寸、焦点与横向溢出。

## Risks / Trade-offs

- [隐藏面板造成状态或焦点丢失] → 保持面板挂载，切换时管理焦点与阅读位置，并用键盘验收。
- [阅读层遮住来源，用户失去上下文] → 显示来源标题和明确关闭入口；关闭后回到触发位置与原结果。
- [预览截断影响引用核对] → 每条都有完整展开入口，引用标记直接展开对应出处，保留原始编号和位置。
- [新规格与尚未归档的检索增量相邻] → 实施前核对 `add-traceable-vector-retrieval` 的 WEB-04/05，确保新需求只是补充呈现，不改变已有检索契约。

## Migration Plan

无数据迁移和后端发布顺序要求。前端实现完成后运行类型检查、构建、现有前端用例及桌面/390px 浏览器验收；若需要回退，可仅回退本次前端呈现改动，既有 API 与材料数据保持可用。
